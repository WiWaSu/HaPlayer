# HaPlayer: суть и принципы

## Что это

HaPlayer — нативное приложение для Windows, которое играет музыку с вашего диска. Внутри нет браузера: ни Electron, ни WebView, ни веб-страницы в окне. По удобству он должен быть на уровне Spotify: открыл, нашёл, включил. Отличие в том, что музыка лежит у вас, плеер работает без интернета и ничего о вас никуда не отправляет.

Стриминг приучил людей к хорошему интерфейсу и одновременно отнял у них музыку. Треки исчезают из каталога, подписка дорожает, история прослушиваний уходит на чужие серверы. Локальные плееры решают эту проблему, но большинство выглядит как программы из 2005 года или требует часа настройки. HaPlayer закрывает этот разрыв.

## Принципы

### 1. Файлы принадлежат пользователю

- Плеер не меняет, не переименовывает и не удаляет файлы без явной команды.
- Теги в файлах не переписываются молча. Если пользователь правит тег в интерфейсе, это отдельное действие с понятной кнопкой.
- Всё, что плеер знает о библиотеке (плейлисты, рейтинги, история), хранится в открытом формате в известной папке. Пользователь может забрать эти данные и уйти к другому плееру.
- Удалили HaPlayer — музыка осталась на месте в том же виде.

### 2. Офлайн по умолчанию

Каждая основная функция работает без сети: сканирование, поиск, воспроизведение, плейлисты. Сетевые функции (подгрузка обложек, текстов песен, обновления) включаются отдельно, и в настройках видно, куда именно идёт запрос.

Скачивание по ссылке (с версии 1.2) работает по тому же правилу. Плеер обращается к сети, только когда пользователь сам вставил ссылку в настройках, и только по этому адресу. Решение общее для всех сайтов: HaPlayer не знает ни одного сайта по имени, не разбирает страницы и ничего не подсказывает. Какую ссылку вставить, решает пользователь, и он же отвечает за то, что скачивает.

Торренты (с версии 1.2) по умолчанию выключены. Пока они выключены, плеер не открывает ни одного сетевого порта. Включаются одним переключателем в настройках, и там же прямо написано, что участники раздачи видят IP-адрес. Правила такие же, как у ссылок: поиска раздач и встроенных каталогов нет, плеер работает только с тем, что пользователь сам вставил или выбрал. Из чужой раздачи скачиваются только аудиофайлы и обложки. Свою папку плеер раздаёт прямо с места и никогда ничего в неё не записывает: если файл в папке изменится, клиент не станет «чинить» его чужой копией (принцип 1).

### 3. Никакой слежки

- Нет телеметрии и аналитики, даже «анонимной».
- Нет рекламы.
- Логи пишутся только на диск пользователя.

Это проверяемое обещание: код будет открыт, и любой может убедиться, что плеер не ходит в сеть без спроса.

### 4. Аккаунт не обязателен

Плеер полностью работает без регистрации. Аккаунт может появиться позже, для синхронизации между устройствами и обмена плейлистами. Если появится, то по модели мессенджера Session:

- аккаунт — это пара ключей, созданная на устройстве; без email и телефона;
- восстановление через фразу из слов, которую хранит сам пользователь;
- всё, что уходит на сервер, зашифровано на устройстве, и сервер не может это прочитать;
- удалить аккаунт можно в любой момент, локальная библиотека при этом не пострадает.

Что именно синхронизировать (только плейлисты и историю или ещё и сами файлы), решим, когда дойдём до этой функции.

### 5. Быстро

Скорость задаём числами, чтобы её можно было проверить. Стартовые цели:

- холодный запуск до 2 секунд;
- список из 50 000 треков прокручивается без рывков;
- поиск по библиотеке отвечает быстрее, чем пользователь допечатает слово;
- повторное сканирование проверяет только изменённые файлы, а не всю папку заново.

- в простое плеер занимает меньше 100 МБ памяти.

Ради этих чисел HaPlayer и пишется нативным приложением. Electron и любые обёртки над браузером тянут за собой целый Chromium: около 150 МБ памяти до загрузки библиотеки, установщик больше 100 МБ, а звук идёт через браузерный аудиостек.

### 6. Звук как в файле

- Плеер ничего не «улучшает» без ведома пользователя: эквалайзер и эффекты по умолчанию выключены.
- Воспроизведение без пауз между треками (gapless) для концертных записей и альбомов, где треки идут один в другой.
- ReplayGain, чтобы громкость не скакала между альбомами.
- Lossless-форматы играются как есть.
- Режим bit-perfect (WASAPI exclusive): плеер отдаёт звук на ЦАП напрямую, мимо микшера Windows и без пересэмплирования. По умолчанию выключен, включается в настройках.
- Поддерживаются форматы, которые встречаются в реальных коллекциях: MP3, FLAC, ALAC, AAC/M4A, Ogg Vorbis, Opus, WAV, AIFF, APE, WavPack. DSD добавим позже.

### 7. Понятно с первого запуска

HaPlayer делается для всех, без расчёта на аудиофилов или любителей настраивать. Раскладку берём привычную по стриминговым сервисам: навигация слева, контент в центре, панель плеера снизу, очередь под рукой. Дизайн и бренд Spotify не копируем, своё лицо у HaPlayer будет своим.

Первый запуск: выбрал папку с музыкой — и через несколько секунд уже можно слушать. Тонкие настройки существуют, но спрятаны и не мешают.

## Чем HaPlayer не будет

- Стриминговым сервисом или магазином музыки.
- Источником пиратского контента. Плеер играет то, что у пользователя уже есть.
- Рекомендательной системой на чужом сервере. Если рекомендации появятся, они будут считаться локально по вашей же истории.
- Социальной сетью с лентой, лайками и подписчиками.
- Видеоплеером. По крайней мере пока: сначала музыка доводится до хорошего состояния.

## Когда принципы спорят

Если две цели тянут в разные стороны, побеждает та, что выше в списке:

1. Целость файлов пользователя.
2. Приватность.
3. Работа без сети.
4. Скорость.
5. Удобство.
6. Новые функции.

Пример: подгрузка обложек из интернета удобна, но нарушает пункты 2 и 3. Поэтому она выключена по умолчанию и включается одной понятной галочкой.

## Платформа

Сначала Windows, и на ней всё должно работать отлично. macOS и Linux пока не поддерживаем, но и закрывать дорогу к ним не стоит. Код, завязанный на Windows (вывод через WASAPI, интеграция с панелью задач и медиаклавишами), держим в отдельном слое, чтобы позже можно было подставить реализацию для других систем.

## Технологии

Правило: нативный интерфейс и нативный звук, никакого HTML внутри.

Стек утверждён 7 ноября 2026:

| Часть | Что берём | Почему |
|---|---|---|
| Язык | C# на .NET 9 | Быстрый, удобный, хорошо поддерживается на Windows. С Native AOT запускается за доли секунды |
| Интерфейс | Avalonia UI | Рисует интерфейс сам через Skia, без браузера. Позволяет сделать свой дизайн в духе стриминговых сервисов. Тот же код позже соберётся под macOS и Linux |
| Вывод звука | NAudio (WASAPI, в том числе exclusive) | Даёт режим bit-perfect на Windows. Лицензия MIT |
| Декодирование | FFmpeg | Читает все форматы из списка выше, включая ALAC, APE и WavPack |
| Теги и обложки | TagLib# | Стандарт для чтения тегов в .NET |
| Библиотека | SQLite | Быстрый поиск по 50 000 треков, один файл, который можно открыть любым просмотрщиком SQLite |

WinUI 3 рассматривали и отказались: он работает только на Windows и сложнее в сборке, а Avalonia оставляет дорогу к macOS и Linux.

Почему не Tauri: он тоже рисует интерфейс веб-страницей, только через встроенный в Windows WebView2. Это та же браузерная модель.

## Открытый код

Проект планируется выложить на GitHub. Лицензию надо выбрать до первого публичного релиза. Варианты:

- GPL-3.0: любой форк тоже обязан остаться открытым. Никто не сможет взять код, добавить слежку и закрыть исходники. Для плеера, который обещает приватность, это сильный аргумент.
- MIT: максимум свободы, код можно брать куда угодно, в том числе в закрытые продукты.

Моё мнение: GPL-3.0 лучше подходит к принципам 3 и 4.

## Как это связано с текущим кодом

Текущий каркас (`electron/`, `src/`, `package.json`) написан на Electron + React. Он противоречит разделу «Технологии», и его надо переписать на нативный стек. Из него стоит перенести:

- раскладку интерфейса: `Sidebar`, `TrackTable`, `PlayerBar`, `TitleBar`;
- белый список аудиорасширений из `electron/main.cjs`;
- правило, что метаданные только читаются и в файлы ничего не пишется.

## Открытые вопросы

- Аккаунты: что синхронизировать и где будет сервер.
- Лицензия. Нужно проверить совместимость с FFmpeg (LGPL) и TagLib# (LGPL); с GPL-3.0 и MIT обе совместимы при динамической линковке.
